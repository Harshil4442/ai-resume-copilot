4. Recommended calibration resolution: prepare a **new versioned supported-format corpus** with declared engine/font/layout cohorts before model execution. Use only font files proven in the native image and pdfLaTeX-compatible source constructs. Independently review and freeze that new corpus and split. Do not edit, silently substitute fonts in, or relabel frozen v1. Retain v1 unsupported inputs as explicit refusal and future format-expansion cases. Alternatively, expand the isolated native compiler/font contract, rebuild its pinned image and repeat complete native/security validation before claiming v1 support. Engine/font expansion is separate work; it is not necessary to truthfully launch a smaller supported-format service.
5. Select a valid reference route and generate the first comparison for the supported PDF subset: interview generation, reference plus candidate, one attempt per side. Use all 10 selected PDF cases, including failures, in the development report. Review these outputs before spending on other services. This is diagnostic calibration, not a 40-pair or worldwide quality pass.
6. After the native boundary and reference/admission gaps below are resolved, expand to the complete 40-pair supported calibration population, then the other six AI operations. Freeze successful candidate versions before separately executing the untouched held-out evaluation. The existing full evidence validator still requires all 200 cases; a 40-case development report must never be marked `evidence_complete`.
