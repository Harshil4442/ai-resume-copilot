# Direct original-resume preview and download

This change lets a candidate preview an original PDF or download an original PDF/DOCX of up to 5 MiB without sending those bytes through the Vercel backend proxy. It reuses the released-upload source-access endpoint. The build-time `NEXT_PUBLIC_RESUME_DIRECT_UPLOAD_ENABLED` flag remains disabled unless its value is exactly `true`. With the flag disabled, the existing original-source route remains in use. Only the enabled flag adds the exact `https://storage.googleapis.com` origin to CSP `connect-src`; all other directives, security headers and redirects are unchanged. TeX source, tailored versions and application artifacts retain their existing routes.

## Request and validation flow

1. The browser makes an authenticated, same-origin GET to `/api/backend/resume/{id}/source-access`. This small JSON response is limited to 8 KiB and must have exactly the six success fields. Duplicate keys are refused, including escaped duplicates. The only legacy fallback is an exact, duplicate-free HTTP 404 body containing `detail.code=direct_source_not_found` and no additional fields.
2. Before any storage request, the browser validates the original filename, PDF/DOCX media type, positive declared size at most 5 MiB, lowercase SHA-256, short expiry and an exact generation-pinned Google V4 URL. Only the HTTPS `storage.googleapis.com` host, a clean object path of the form `/{bucket}/clean/rup_{32 lowercase hex characters}/source`, and the eight approved signing/generation/media query fields are accepted. Encoded path aliases, redirects, alternate ports, extra or duplicate query parameters, expired grants and invalid calendar dates are refused.
3. The browser makes one signed GET, with credentials omitted, no referrer, no-store caching and redirects refused. It requires the exact URL and media type, and validates Content-Length if present. The response stream cannot exceed the declared size; completion must match that size exactly. SHA-256 must match before a Blob can be returned. The signed URL stays transient and is never returned by the helper, stored, logged or included in errors.
4. The PDF preview uses a local Blob URL. The original download uses a local Blob URL and the validated filename. URLs are revoked on cleanup. Selection changes, owner changes and unmounts cancel pending direct requests and prevent stale completion from publishing a preview or download. A 45-second browser deadline covers metadata, storage reading and verification; no automatic retry is added.

The helper shares this flow with `fetchResumeSource` and the original-download control. One invocation performs one metadata request and at most one storage request; preview and a later download are separate user actions and therefore each obtains its own short-lived grant. A client cannot independently verify the Google signature cryptographically; the authenticated metadata authority, strict target contract and byte hash are the bindings used here. Local object URLs do not contain the signed capability. Google documents signed URLs as time-limited bearer capabilities using XML API endpoints; the shorter 60-second limit and restricted signing shape here are HireWiz policy. [Google signed URLs](https://docs.cloud.google.com/storage/docs/access-control/signed-urls).

## Required joined backend change

The missing-direct-binding fallback requires the accompanying backend source-access compatibility change. It may emit `direct_source_not_found` only for an owned legacy Resume with no retained direct binding. A retained binding that is unreleased, invalid, orphaned or associated with another owner must remain a refusal, including when a narrower owner filter would otherwise hide that binding. Missing/unowned resumes use a different error code. Generic 404, 401, 403, 409, 503, network errors, malformed metadata, wrong bytes and hash mismatches never fall back.

The legacy fallback retains its existing byte transport and does not gain a SHA-256 receipt through this change. The flag must not be enabled independently of that reviewed backend distinction and the release gates below.

## Verification and deployment limits

- Focused synthetic tests cover the exact 5 MiB byte/hash boundary, strict signing/origin/generation fields, duplicate-free JSON, refusals, bounded reading, abort/deadline cleanup, owner/selection changes and compatibility routes. The full frontend unit, type, lint and normal Turbopack build checks remain required.
- A browser fixture verifies the enabled original-preview/download flow at widths 320, 390, 768, 1024 and 1440 on a normal Turbopack production build. It uses synthetic API/storage replies and a local signed session, and verifies the downloaded bytes and preview Blob hash. The fixture does not establish native GCS IAM, signature validity, CORS or production authentication behavior. A preceding normal build with the flag disabled and explicit CSP controls cover the default behavior. Original fixture and CSP refusals remain in the private evidence packet; they are not production failure observations.
- Native bucket CORS must permit the intended frontend origins and GET access before activation. Header exposure must be checked if Content-Length validation is expected in the browser. Bucket privacy, signer permissions, released-upload ownership, exact generation access, worker receipt enforcement and cleanup remain deployment requirements. [Google Cloud Storage CORS](https://docs.cloud.google.com/storage/docs/cross-origin).
- Legacy originals over Vercel's request/response transport ceiling and large application/version artifacts are not fixed by this path. It covers released direct-upload original PDF/DOCX files only. API upload, quarantine scanning, schema 0014, coordinator IAM/SQL permissions, monetary fencing and protected employer integration remain separate gates.
- The helper buffers at most the declared 5 MiB file plus bounded temporary copies for hashing/Blob creation. No performance improvement, native isolation, paid activation or global credential retirement is claimed by these source tests.
